# VEP Annotation Process for UKB and AoU using Docker

## Original Repository

This repository is a fork of the `vep_ukb_aou_docker` repository, originally created by Andy Wood at the University of Exeter. This updated version changes the VEP version to v115 and 
updates the associated annotation files. It also adds corrects a bug in constraint scores.

Full credit for the original framework, Docker setup, and VEP command structure goes to Andy Wood.

## Future questions to Michael Weedon (M.N.Weedon@exeter.ac.uk)
The version of [VEP](https://www.ensembl.org/info/docs/tools/vep/index.html) and associated plugins used to annotate variants in UK Biobank and All of Us in Exeter 2025 have been containerized through Docker.
The purpose is for 1) the reproducibility of annotations generated by Exeter for UK Biobank and All of Us, and 2) the provision of a working version of VEP without the hassle of a manual install of VEP 
and required plugins.
Annotations of variants captured through WGS in UK Biobank and All of Us was performed using Ensembl v115. This version will be used when the Docker container is run. 
Steps to perform annotation of variants using the Docker container are:

 1. Download data dependencies for both VEP and the plugins used
 2. Prepare and place vcf site list in vep data directory
 3. Pull down and build Docker image
 4. Mount local data directory to container and run

Note, the Dockerfile has been included in this repo for completeness - you do not need it to follow the instructions below.

## Get the data dependences used for VEP
Data related to v115 of the VEP cache, fasta files, custom annotations, and plugin data dependencies can be found 
[here](https://console.cloud.google.com/storage/browser/vepdata;tab=objects?forceOnBucketsSortingFiltering=true&authuser=1&project=local-pointer-430908-c7&prefix=&forceOnObjectsSortingFiltering=false).
Scripts have been provided based on gsutil and wget. Both of the file scripts above will download the required data into a new directory called `vep_data`.

```
# gsutil
bash get_vep_data_gsutil.sh
```
or
```
# wget
bash get_vep_data_wget.sh
```

This will take some time as the size of the data is ~250Gb, but only has to be done once. If running on DNAnexus cloud workstation, it would beneficial to create a snapshot so you don't have to download again but instantiate a snapshot instead.


## Get the site list for ready for VEP
The vcf needs to simply include the first 5 columns of a standard VCF (after headers) - CHROM, BP (b38), ID, REF and ALT. You should place the input site list vcf into the `vep_data` directory as well.


## Get image and build the Docker container
You can pull down the Docker image from the Docker repo site using the following command:
```
sudo docker pull weedonml/vep
```

# an example to build the docker 
docker build -t weedonml/vep_ukb_aou_docker:v115 .

## Run VEP using Docker
Once the Docker containiner has been built, you can run VEP ensuring you have mounted the `vep_data` directory to `/usr/data/` inside the container. For DNANexus - put vep_data in /home/dnanexus/vep_data
The following is an example command assuming the above has been performed on DNAnexus cloud workstation and the chr22 site list for UK Biobank is to be put through VEP.
Note the mounting of the local directory to the container directory is given as `/home/dnanexus/vep_data:/usr/data` within the following command, where `chr22.vcf` is an input VCF and `chr22.vep` is the name of the output file to be produced by VEP:
```
sudo docker run -itv /home/dnanexus/vep_data:/usr/data weedonml/vep_ukb_aou_docker:v115 vep \
  -i /usr/data/ukb24310_c17_ALL_v1_var_list_indels_normalised.vcf \
  -o /usr/data/ukb24310_c17_ALL_v1_var_list_indels_normalised.vep \
  --tab \
  --assembly GRCh38 \
  --offline \
  --cache \
  --dir_cache /usr/data/ \
  --fasta /usr/data/fasta/Homo_sapiens.GRCh38.dna.toplevel.fa.gz \
  --everything \
  --fork 64 \
  --no_stats \
  --custom /usr/data/custom_annotations/riboseq_mudge_et_al_st2_data_ARW.bed.gz,riboseq_orf,bed,overlap,0 \
  --custom /usr/data/custom_annotations/chen_constraint_z_Supplementary_Data_2_region_labels_with_constraint.sorted.bed.gz,constraint_z_region,bed,overlap,0 \
  --custom /usr/data/custom_annotations/phastConsElements30way_region_labels.bed.gz,phast_cons_30way_region,bed,overlap,0 \
  --custom /usr/data/custom_annotations/phastConsElements30way_lod.bed.gz,phast_cons_30way_lod,bed,overlap,0 \
  --custom /usr/data/custom_annotations/phastConsElements30way_score.bed.gz,phast_cons_30way_score,bed,overlap,0 \
  --custom /usr/data/custom_annotations/phastConsElements100way_region_labels.bed.gz,phast_cons_100way_region,bed,overlap,0 \
  --custom /usr/data/custom_annotations/phastConsElements100way_lod.bed.gz,phast_cons_100way_lod,bed,overlap,0 \
  --custom /usr/data/custom_annotations/phastConsElements100way_score.bed.gz,phast_cons_100way_score,bed,overlap,0 \
  --custom /usr/data/custom_annotations/jarvis_ranked_deduplicated.17.hg38.score.bed.gz,jarvis_score,bed,exact,0 \
  --custom /usr/data/custom_annotations/jarvis_ranked_deduplicated.17.hg38.percentile_score.bed.gz,jarvis_score_percentile,bed,exact,0 \
  --custom /usr/data/custom_annotations/promoterAI_tss500_no_version.vcf.gz,promoterAI,vcf,exact,0,promoterAI_score,promoterAI_transcript \
  --plugin CADD,/usr/data/plugin_data/whole_genome_SNVs.tsv.gz,/usr/data/plugin_data/gnomad.genomes.r3.0.indel.tsv.gz \
  --plugin Conservation,/usr/data/plugin_data/gerp_conservation_scores.homo_sapiens.GRCh38.bw \
  --plugin SpliceAI,snv=/usr/data/plugin_data/spliceai_scores.raw.snv.hg38.vcf.gz,indel=/usr/data/plugin_data/spliceai_scores.raw.indel.hg38.vcf.gz \
  --plugin REVEL,/usr/data/plugin_data/new_tabbed_revel_grch38.tsv.gz \
  --plugin LoF,loftee_path:/usr/.vep/Plugins/loftee,gerp_bigwig:/usr/data/plugin_data/gerp_conservation_scores.homo_sapiens.GRCh38.bw,human_ancestor_fa:/usr/data/plugin_data/human_ancestor.fa.gz,conservation_file:/usr/data/plugin_data/loftee.sql \
  --plugin UTRannotator,/usr/.vep/Plugins/UTRannotator/uORF_5UTR_GRCh38_PUBLIC.txt \
  --plugin AlphaMissense,file=/usr/data/plugin_data/AlphaMissense_hg38.tsv.gz \
  --plugin EVE,file=/usr/data/plugin_data/eve_merged.vcf.gz \
  --plugin PrimateAI,/usr/data/plugin_data/PrimateAI_scores_v0.2_GRCh38_sorted.tsv.bgz \
  --plugin SpliceRegion 
```

Notes:
 * Jarvis score files are chromosome specific, and no Jarvis files exist for chromosomes X, Y or MT.
 * You may want to amend the number of forks depending on the number of processors available to you. For UKB and AoU on the DNAnexus platform, `--fork 64` was used.
 * If running chromosome-wide site lists for UKB / AoU, it is strongly recommended you do this either one chromosome at a time, or in parallel across multiple cloud workstations.
 * The default worker used for AoU and UKB was `mem1_ssd1_v2_x72`
 * If placing above command in script on DNAnexus, its a good idea to use the following command once you uploaded the results to your project: `dx-set-timeout 0s`
 * Compression ratio is high given repeating sequences of `-` when gzip compressing output from VEP.
